Hub de Leitura: API com Cypress

Testes automatizados de API em um sistema de biblioteca, com foco no que mais quebra em produto real: regras de negócio e quem pode fazer o quê.

CypressAllure ReportGitHub ActionsAutorização por perfil

Contexto

O Hub de Leitura é um sistema de biblioteca com usuários de perfis diferentes. Em sistemas assim, o risco maior costuma estar na API: uma regra de negócio mal aplicada ou uma permissão que vaza dá acesso indevido a quem não deveria.

O que foi testado

  • Regras de negócio da biblioteca, validadas direto na API.
  • Autorização por perfil: o que cada tipo de usuário pode e não pode fazer, incluindo as tentativas que precisam ser bloqueadas.

Estratégia

Testar pela API é mais rápido e mais estável do que pela interface, e permite cobrir cenários de permissão em volume. Por isso as regras e os perfis foram o centro da suíte.

Permissão não é só "o usuário certo consegue". O teste importante é "o usuário errado não consegue".

Pipeline e relatórios

A execução roda no GitHub Actions e gera relatórios Allure, para que qualquer pessoa do time veja o resultado sem rodar nada localmente.

Práticas que adoto nos meus projetos de automação

  • Comandos customizados e centralização de requisições, para evitar código duplicado.
  • Massa de dados com fixtures e Faker.
  • Mapeamento de cenários baseado em risco, guiando o que automatizar primeiro.
